# Spec: `bespoke` CLI

The only supported way to create, deploy, and operate apps. Agents and humans
alike use it; hand-editing generated artifacts (Caddy routes, systemd units,
Litestream config) is forbidden by convention.

## Commands

### `bespoke new <slug>`

1. Validate `slug` against the [manifest spec](app-manifest.md) and uniqueness.
2. Scaffold `apps/<slug>/` from the template (manifest, `main.go`, `app.go`,
   `views/`, `migrations/0001_init.sql`).
3. Assign the next free port (sequential from 4101) into `app.toml`.
4. Generate and enable the systemd user unit (stopped until first deploy).

Exit non-zero without side effects on any validation failure.

### `bespoke deploy <slug>`

Runs on the dev machine; remote hosts per
[ADR-0011](../adr/0011-split-host-deployment.md).

1. `GOOS=linux go build -o bin/apps/<slug> ./apps/<slug>` — abort on compile
   error.
2. rsync the binary, manifest, and generated unit to the app host (`selfie`);
   restart `bespoke-<slug>.service`; wait for a `200` from
   `<selfie>:<port>/healthz` (provided by `pkg/web`) within 10s, else roll
   back to the previous binary and exit non-zero.
3. Regenerate the Caddy route import and Litestream config from all manifests;
   push the route file to the edge host and `caddy reload` (no-op if
   unchanged).

### `bespoke list`

Registry dump: slug, name, port, unit state, last deploy time. `--json` for
agents.

### `bespoke logs <slug> [-f]`

Wrapper for `journalctl --user -u bespoke-<slug>`.

### `bespoke rm <slug>`

Stop + disable the unit, remove generated route/backup entries, archive
`data/<slug>.db` to `data/archive/`, and delete `apps/<slug>/` only with
`--force`. Never deletes database files.

## Behavior contract

- Idempotent: re-running any command converges to the same state.
- All generated artifacts carry a `# GENERATED by bespoke — do not edit` header.
- Every command that changes state prints the artifacts it touched.
- `--json` output is stable; it is the agent-facing API.
