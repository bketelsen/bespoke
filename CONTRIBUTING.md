# Contributing to Bespoke

First, the unusual part: Bespoke is a *personal* platform. The apps in this
repo are mine; yours belong in your fork (start at
[MAKE-IT-YOUR-OWN.md](MAKE-IT-YOUR-OWN.md)). What we share is the platform —
the conventions, `pkg/*`, platformd, the `bespoke` CLI, the agent skills,
and the docs tree. Contributions that make *every* fork better are very
welcome.

## Good contributions

- Platform fixes and capabilities: `pkg/{web,ui,auth,db,llm,audio}`,
  `platform/`, `cmd/bespoke/`
- Agent-facing improvements: [AGENTS.md](AGENTS.md), skills under
  [.agents/skills/](.agents/skills/), doc templates
- Docs: corrections, broken cross-links, clearer specs
- Bug fixes in my apps (they double as reference implementations)

New apps and personal-taste changes (theme, app features) belong in your
fork — that's the whole point.

## Dev setup

You need Go (version pinned in [go.mod](go.mod)),
[`just`](https://github.com/casey/just), and
[`golangci-lint`](https://golangci-lint.run/) v2 (version pinned in
[.github/workflows/ci.yml](.github/workflows/ci.yml)). Then:

```sh
just dev     # platformd + every app on localhost with a fake identity
just check   # vet + tests + lint + tidy + CGO-free linux cross-compile
```

`just check` is exactly what CI runs — if it passes locally, CI passes.

Only needed if you touch `.templ` files or the theme: run
`scripts/setup-tools.sh` once, then `scripts/build-ui.sh` after each change,
and **commit the generated** `*_templ.go` and `pkg/ui/assets/styles.css`.
Builds and CI never run the UI toolchain.

## Ground rules (the short version)

The long version is [AGENTS.md](AGENTS.md) — it's written for coding agents,
which makes it unusually explicit for humans too.

- Significant decisions get an ADR first (`docs/adr/`, from the template),
  then the affected design docs/specs in the same change.
- Docs cross-link in both directions; a doc missing its links is incomplete.
- Never hand-edit `pkg/ui/components/` (vendored via templUI) or `dist/gen/`
  (generated by the CLI).
- No cgo, no new auth paths, no hardcoded ports.

## Sending changes

Fork, branch, `just check`, open a PR. The PR template has the checklist.
Small focused PRs land fast; anything that changes a contract should point
at its ADR.
